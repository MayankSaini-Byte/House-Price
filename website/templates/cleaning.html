Data Cleaning Process

Step-by-step walkthrough of how we handled missing values, treated numerical and categorical features, and prepared the dataset for machine learning.

1

Categorical Missing Values → Fill with "None"

Many categorical features have missing values that don't represent "unknown data" — they mean the property lacks that feature entirely. For example, a missing PoolQC means "no pool," not "pool quality unknown."

Python 
# Columns where NaN means "feature not present"
cols_none = [
    'Alley', 'MasVnrType', 'BsmtQual', 'BsmtCond',
    'BsmtExposure', 'BsmtFinType1', 'BsmtFinType2',
    'FireplaceQu', 'GarageType', 'GarageFinish',
    'GarageQual', 'GarageCond', 'PoolQC',
    'Fence', 'MiscFeature'
]

# Fill NaN with "None" to indicate absence
train[cols_none] = train[cols_none].fillna("None")
test[cols_none] = test[cols_none].fillna("None")
Why This Is Necessary

If we left these as NaN, the model would either crash (sklearn doesn't handle NaN in categorical features) or impute them incorrectly. By filling with "None," we preserve the semantic meaning: this is a valid category representing "absence." The OneHotEncoder will then create a binary column for "None," letting the model learn that having no pool/garage/basement is a distinct property characteristic.

Expected Output

After this step, columns like PoolQC go from having 1,453 NaN values to having 1,453 "None" values. The column is now complete with no missing data, and every value is a valid category string.

2

LotFrontage → Neighborhood Median Imputation

LotFrontage (linear feet of street connected to the property) has 259 missing values. Unlike the categorical features above, this is genuinely missing data that we need to estimate.

Python 
# Impute LotFrontage using the median of each Neighborhood
train['LotFrontage'] = train.groupby('Neighborhood')['LotFrontage'].transform(
    lambda x: x.fillna(x.median())
)
Why Neighborhood Median?

Properties in the same neighborhood tend to have similar lot sizes and frontages due to zoning regulations and subdivision design. Using the global median would treat a rural property and a downtown townhouse the same. The neighborhood-specific median is a much more accurate estimate because it accounts for local lot patterns. This technique is called group-wise imputation.

3

Numerical Features → Zero Fill

For features like MasVnrArea (masonry veneer area) and GarageYrBlt (year garage was built), missing values mean the feature doesn't exist — no veneer, no garage.

Python 
# No masonry veneer = 0 square feet of veneer area
train['MasVnrArea'] = train['MasVnrArea'].fillna(0)

# No garage = year built is 0 (sentinel value)
train['GarageYrBlt'] = train['GarageYrBlt'].fillna(0)
Why Not Median or Mean?

Using the median here would be misleading. If a house has no masonry veneer, assigning the dataset's average veneer area would incorrectly tell the model "this house has some veneer." Zero correctly communicates "this feature is absent." For GarageYrBlt, zero serves as a sentinel value — the model will learn that houses with GarageYrBlt=0 are fundamentally different (they have no garage at all).

4

Electrical → Mode Imputation

Electrical has only 1 missing value. Since every house has an electrical system, this is genuinely missing data — we fill with the most common value.

Python 
# Fill the single missing Electrical value with the mode
train['Electrical'] = train['Electrical'].fillna(
    train['Electrical'].mode()[0]
)
Why Mode?

For categorical features with genuine missing data (not "absence"), the mode (most frequent value) is the safest imputation strategy. Since "SBrkr" (Standard Circuit Breakers) accounts for ~91% of values, it's a statistically sound assumption. With only 1 missing value out of 1,460, the impact on model performance is negligible regardless of imputation strategy.

5

Encoding Strategy — Preprocessing Pipeline

After cleaning, we apply a ColumnTransformer that handles numeric and categorical features differently through separate sub-pipelines.

Python 
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler, OneHotEncoder

# Identify column types
num_cols = X_train.select_dtypes(include=['int64', 'float64']).columns
cat_cols = X_train.select_dtypes(include=['object']).columns

# Build the preprocessing pipeline
preprocessor = ColumnTransformer([
    ('num', Pipeline([('scaler', StandardScaler())]), num_cols),
    ('cat', Pipeline([('encoder', OneHotEncoder(
        handle_unknown='ignore',
        sparse_output=False
    ))]), cat_cols)
])
How It Works

StandardScaler normalizes numeric features to have mean=0 and std=1. This is critical for distance-based models (SVR, KNN) where features with larger scales would dominate. OneHotEncoder converts each categorical value into a binary column (e.g., Neighborhood_NAmes=1, Neighborhood_NridgHt=0). The handle_unknown='ignore' parameter ensures the pipeline doesn't crash if test data contains categories not seen during training.

Expected Output

After transformation, the feature matrix expands from ~80 columns to ~280+ columns (due to one-hot encoding). Each numeric feature is centered around 0, and each categorical feature is represented as a set of binary indicator columns.
