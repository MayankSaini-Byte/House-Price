Problem Statement

Given a set of features describing a residential property (location, size, quality, condition, amenities, etc.), predict the final sale price. This is a supervised regression problem where the target variable (SalePrice) is continuous.

The dataset comes from the Kaggle House Prices competition , which challenges participants to build models that accurately predict house prices in Ames, Iowa. The evaluation metric is RMSE on log-transformed predictions.

Dataset Description

The Ames Housing dataset was compiled by Dean De Cock as an alternative to the frequently cited Boston Housing dataset. It contains 1,460 training observations and 80 features, with a test set of 1,459 observations (without sale prices).

Feature Categories

  • Location: Neighborhood, Condition1/2, MSZoning
  • Size: LotArea, GrLivArea, TotalBsmtSF, GarageArea
  • Quality: OverallQual, OverallCond, ExterQual, KitchenQual
  • Age: YearBuilt, YearRemodAdd, GarageYrBlt
  • Amenities: Fireplaces, PoolArea, Fence, MiscFeature
  • Structure: BldgType, HouseStyle, RoofStyle, Foundation
  • Utilities: Heating, CentralAir, Electrical
  • Sale: SaleType, SaleCondition, MoSold, YrSold

Workflow

The project follows a standard machine learning pipeline:

  • Data Loading: Read CSV files using pandas
  • Exploratory Analysis: Visualize distributions, correlations, missing values
  • Data Cleaning: Handle missing values using domain-appropriate strategies
  • Feature Engineering: Create 10 new features using domain knowledge
  • Preprocessing: StandardScaler for numerics, OneHotEncoder for categoricals
  • Model Training: Train 5 regression models
  • Evaluation: Compare using R², MAE, RMSE on held-out test set
  • Deployment: Best model served via Flask API for interactive predictions

Data Cleaning Process

19 columns contained missing values. We applied three distinct imputation strategies based on the semantic meaning of each missing value:

  • "None" fill (15 columns): Categorical features where NaN means the feature is absent (e.g., no pool, no fence, no garage)
  • Zero fill (3 columns): Numerical features where NaN means zero area/age (MasVnrArea, GarageYrBlt, and test-set numerical columns)
  • Smart imputation: LotFrontage filled using neighborhood median; Electrical filled with dataset mode

For the test set, additional columns had missing values (MSZoning, Utilities, etc.). These were filled using the mode of the training data to prevent data leakage.

Feature Engineering Process

We created 10 new features from existing columns, each motivated by real-estate domain knowledge:

  • HouseAge / RemodAge: Time-based features capturing depreciation and renovation recency
  • TotalSF: Combined above-ground and basement area into total usable space
  • TotalBath: Weighted sum of all bathroom types (full=1, half=0.5)
  • TotalPorchSF: Sum of all porch/deck areas
  • OverallScore: Interaction term between quality and condition
  • HasPool / HasGarage / HasFireplace / HasBasement: Binary presence indicators

Modeling Process

Five regression algorithms were trained and evaluated:

  • Linear Regression: Baseline model with no hyperparameters. Works well due to our feature engineering and log transformation.
  • Random Forest: Ensemble of 100 decision trees with bagging. Provides feature importance rankings.
  • Gradient Boosting: Sequential ensemble with 200 trees, learning rate 0.1, max depth 4.
  • SVR: Support Vector Regressor with RBF kernel. Limited by iteration count on this dataset size.
  • KNN: K=5 nearest neighbors. Suffers from curse of dimensionality with 280+ encoded features.

The target variable was log-transformed using np.log1p before training. All predictions are reverse-transformed using np.expm1 for evaluation in dollar terms.

Evaluation Process

Models were evaluated on a held-out 20% test set (292 houses) using three metrics:

  • R² Score: Proportion of variance explained (1.0 = perfect). Our best: ~0.90
  • MAE (Mean Absolute Error): Average prediction error in dollars
  • RMSE (Root Mean Squared Error): Penalizes large errors more heavily

Linear Regression achieved the highest R², demonstrating that well-engineered features can make simple models outperform complex ones.

Future Improvements

  • Hyperparameter tuning: Use GridSearchCV or Optuna to systematically optimize model parameters
  • Stacking/Blending: Combine predictions from multiple models for better accuracy
  • Advanced models: Try XGBoost, LightGBM, or CatBoost with proper tuning
  • Target encoding: Use target encoding for high-cardinality categorical features instead of one-hot
  • Cross-validation: Implement K-fold CV instead of single train/test split for more robust evaluation
  • Outlier removal: Identify and remove or cap outliers in GrLivArea and SalePrice
  • More feature engineering: Polynomial features, log transforms of skewed features
  • Regularization: Use Ridge/Lasso/ElasticNet to handle multicollinearity

Lessons Learned

  • Feature engineering > model complexity: Well-crafted features enable simple models to compete with or outperform complex ones
  • Domain knowledge is crucial: Understanding real-estate valuation guided every cleaning and engineering decision
  • Missing values carry information: In this dataset, most "missing" values actually mean "feature absent" — a meaningful signal, not noise
  • Log transform the target: When the target is right-skewed (as prices often are), log transformation significantly improves model performance
  • Scale your features: Distance-based models (SVR, KNN) are very sensitive to feature scales. StandardScaler is essential.
  • Evaluate on unseen data: Training accuracy is meaningless — only test set performance tells you if the model truly learned
